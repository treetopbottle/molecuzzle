# Start a project

1. Fill in the README: why, who, what. Development waits for the setup plan.
2. Write the spec: its scope, the rules of the first feature with examples, and a narrative.
3. Fill the backlog in `docs/plans/README.md`. The first slice is setup.
4. **Checkpoint.** Show the README, the spec and the backlog. Wait for an OK, then commit.
5. [Write a plan](write-a-plan.md) for setup, with no rule ids: decision 0001 on the language, the tooling, the Development commands, and the test helpers that translate the spec's rules into tests. A snapshot of the state as text works well, kept inline in the test: e.g. Rust `insta`, Python `inline-snapshot`.
